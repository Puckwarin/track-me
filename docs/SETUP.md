# Project Setup — ทำครั้งแรก (v1.2)

เอกสารนี้คือสิ่งที่ **คุณต้องทำเอง** ครั้งแรกหลังได้โค้ด v1.2 ไปแล้ว (โค้ดทั้งหมดผมเขียนให้แล้ว แต่ผมเข้า Firebase Console / GitHub ของคุณไม่ได้)
ทุกขั้นตอนใช้ **แผนฟรี ไม่ต้องผูกบัตรเครดิต**

> ⚠️ **ลำดับสำคัญ:** ทำตามเลขข้อต่อกันไป โดยเฉพาะข้อ 4–6 (ย้ายข้อมูลเดิม) — ถ้าเปลี่ยน Rules เป็นแบบสุดท้ายก่อนย้ายข้อมูล ข้อมูลเดิมจะอ่านไม่ได้

## 0) สิ่งที่ต้องมี
- บัญชี Google (ใช้ทั้ง Firebase และล็อกอินในแอป)
- บัญชี GitHub และ repo `Puckwarin/track-me` (ตั้งเป็น **Public** — GitHub Pages ฟรีใช้กับ repo สาธารณะ; repo ส่วนตัวต้องใช้แผนเสียเงิน)
- (ถ้าจะพัฒนาบนเครื่อง) Node.js 20 ขึ้นไป

## 1) Firebase: ตรวจแผนและเปิด Google Sign-in
เปิด [Firebase Console](https://console.firebase.google.com) → เลือกโปรเจกต์ `trackme-2829`

1. **ตรวจแผน:** มุมซ้ายล่างต้องเป็น **Spark (No-cost)** — ไม่ต้องกด Upgrade เลย
2. ไปที่ **Build → Authentication → Get started** (ถ้ายังไม่เคยเปิด)
3. แท็บ **Sign-in method** → เลือก **Google** → เปิด **Enable** → ใส่ *Project support email* (อีเมลของคุณ) → **Save**
4. แท็บ **Settings → Authorized domains** → **Add domain** ใส่ `puckwarin.github.io`
   (`localhost` มีอยู่แล้วโดยปริยาย สำหรับพัฒนาบนเครื่อง)

## 2) ดันโค้ดขึ้น GitHub และเปิด GitHub Pages
1. อัปโหลด/push โค้ดทั้งโฟลเดอร์ขึ้น branch `main` (รวมโฟลเดอร์ `.github/workflows/` และ `package-lock.json`)
2. ใน GitHub: **Settings → Pages → Build and deployment → Source** เลือก **GitHub Actions**
   (ของเดิมน่าจะเป็น "Deploy from a branch" — ต้องเปลี่ยน ไม่เช่นนั้นจะเห็นหน้าเปล่า)
3. ดูแท็บ **Actions** ให้ workflow "Deploy to GitHub Pages" ขึ้นเขียว (ใช้เวลา 1–2 นาที)
4. เว็บอยู่ที่ `https://puckwarin.github.io/track-me/`

## 3) Firestore Rules ชุดย้ายข้อมูล (ชั่วคราว)
Firebase Console → **Build → Firestore Database → Rules**

1. คัดลอกเนื้อหาไฟล์ **`firestore.rules.migration`** ไปวางทับ → **Publish**
   (ชุดนี้ให้เฉพาะผู้ที่ล็อกอินแล้วอ่านข้อมูล Room Code เดิมได้ชั่วคราว)

## 4) ล็อกอินและย้ายข้อมูลเดิม
1. เปิดเว็บ → กด **เข้าสู่ระบบด้วย Google**
2. ไปที่ **ตั้งค่า → ย้ายข้อมูลจาก Room Code เดิม** → ใส่รหัสห้องเดิม (ถ้าเคยตั้งในเครื่องนั้นไว้ ช่องจะกรอกให้) → **ตรวจสอบ**
3. กด **ย้ายเข้าบัญชีนี้** → ตรวจในแท็บอาหาร/ประจำเดือน/น้ำหนักว่าข้อมูลครบ (ย้ายซ้ำได้ ไม่เกิดข้อมูลซ้ำ)
4. **แนะนำ:** กด **สำรองข้อมูล (JSON)** ใน ตั้งค่า เก็บไว้ก่อน
5. ถ้ามีหลายห้อง/หลายอุปกรณ์ที่เคยใช้รหัสห้องคนละรหัส ให้ทำข้อ 2–3 ซ้ำกับแต่ละรหัส

## 5) เปลี่ยนเป็น Rules ชุดสุดท้าย
Firebase Console → **Firestore Database → Rules**

1. คัดลอกเนื้อหาไฟล์ **`firestore.rules`** วางทับ → **Publish**
2. ทดสอบที่แท็บ **Rules Playground**: อ่าน `/users/ไอดีใครก็ได้/food_records/x` โดยไม่ล็อกอิน ต้องเป็น **Denied**
3. กลับมารีเฟรชแอป ต้องเห็นข้อมูลปกติ

> ข้อมูลเดิมแบบ Room Code (collection ระดับบน) จะอ่านไม่ได้แล้ว — ถ้าต้องการลบทิ้ง ให้กดปุ่ม "ลบข้อมูลเดิมในห้องนี้" ในหน้าย้ายข้อมูล **ก่อน** ทำข้อ 5 หรือลบเองใน Firebase Console

## 6) (ตัวเลือก) Gemini API Key สำหรับถ่ายรูปอาหาร/ฉลาก
ฟีเจอร์ AI ใช้คีย์ **ของคุณเอง** (ผมทำ backend ให้ไม่ได้ในแผนฟรี)

1. เข้า [Google AI Studio → API keys](https://aistudio.google.com/apikey) → **Create API key** (ระดับฟรีไม่ต้องผูกบัตร)
2. คัดลอกคีย์ → ในแอป **ตั้งค่า → Gemini API Key** → วาง → บันทึก
3. ต้องใส่ **ทุกอุปกรณ์** (คีย์เก็บในเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่ซิงค์ ไม่อยู่ในไฟล์สำรอง)
4. อย่าเอาคีย์ไปใส่ในโค้ดหรือ push ขึ้น GitHub — ถ้าคีย์หลุดให้ลบแล้วสร้างใหม่ใน AI Studio
5. โควตาและเงื่อนไขของระดับฟรีเปลี่ยนได้ (รวมถึงเรื่องการใช้ข้อมูลที่ส่งไป) — ตรวจหน้าเว็บของ Google ก่อนใช้ ภาพอาหาร/ฉลากที่ส่งจะถูกส่งไปที่ Google

## 7) พัฒนาบนเครื่อง (ตัวเลือก)
```bash
npm install
npm run dev        # เปิด http://localhost:5173/track-me/
npm run build      # ผลลัพธ์ที่ dist/
```

## 8) ติดตั้งเป็นแอปบนมือถือ + ทดสอบออฟไลน์
1. เปิด `https://puckwarin.github.io/track-me/` ตอนออนไลน์ ล็อกอิน แล้วรอให้ข้อมูลโหลด **1–2 ครั้ง**
2. Android (Chrome): เมนู ⋮ → **Add to Home screen / Install app** · iPhone (Safari): ปุ่มแชร์ → **Add to Home Screen**
3. ทดสอบ: เปิดโหมดเครื่องบิน → เปิดแอป → ต้องเห็นการ์ด "สรุปสุขภาพล่าสุด" พร้อมเวลาซิงค์ล่าสุด และบันทึกข้อมูลใหม่ได้ (ป้ายขึ้น "ออฟไลน์ · รอซิงค์") พอกลับมาออนไลน์จะซิงค์เอง

## แก้ปัญหาที่พบบ่อย
| อาการ | วิธีแก้ |
|---|---|
| `auth/unauthorized-domain` | เพิ่ม `puckwarin.github.io` ใน Authentication → Settings → Authorized domains (ข้อ 1.4) |
| `auth/operation-not-allowed` | ยังไม่ได้ Enable Google ใน Sign-in method (ข้อ 1.3) |
| ป้ายเป็นสีแดง `permission-denied` | Rules ยังไม่ได้ Publish / ยังไม่ล็อกอิน / ใช้ชุด Rules ผิดขั้นตอน (ดูข้อ 3 และ 5) |
| เว็บขึ้นหน้าเปล่าหรือ 404 | Pages Source ต้องเป็น GitHub Actions และ workflow ต้องผ่าน (ข้อ 2) |
| แก้โค้ดแล้วเว็บไม่เปลี่ยน | แอปอัปเดตเองเมื่อเปิดครั้งถัดไป ลองปิดแอปทั้งหมดแล้วเปิดใหม่ หรือล้างข้อมูลเว็บไซต์ |
| ล็อกอินไม่ได้ในแอปที่ติดตั้งบน iPhone | ผมยังไม่ได้ทดสอบบนอุปกรณ์จริง — ลองล็อกอินผ่านเบราว์เซอร์ปกติแทนการใช้ไอคอนบนหน้าจอ (ยังใช้ออฟไลน์ได้) |
| Pop-up ล็อกอินถูกบล็อก | อนุญาต pop-up ของเว็บนี้ในเบราว์เซอร์ |

## ขีดจำกัดแผนฟรี (Spark) ที่ควรรู้
- Firestore: อ่าน 50,000 ครั้ง/วัน (ใช้คนเดียวเหลือเฟือ) — เลิกฟังข้อมูลเมื่อไม่ใช้ แอปนี้ดึงเฉพาะข้อมูลที่ต้องใช้
- ถ้าเกินโควตา Firebase จะหยุดให้บริการจนถึงวันถัดไป **ไม่เรียกเก็บเงิน** (เพราะไม่ได้ผูกบัตร)
- ต้องไม่กด Upgrade เป็น Blaze ถ้าไม่ต้องการผูกบัตร

## ความเป็นส่วนตัวบนอุปกรณ์ร่วม
หลังออกจากระบบ ข้อมูลที่เคยโหลดอาจยังค้างในแคชของเบราว์เซอร์เครื่องนั้น — ถ้าใช้เครื่องสาธารณะ/เครื่องร่วม ให้ล้างข้อมูลเว็บไซต์ (Clear site data) หลังใช้

## อัปเดต v1.3 — ทำเพิ่มหลังได้โค้ดชุดนี้

### A) ต้อง Publish Firestore Rules ใหม่ (สำคัญ)
v1.3 เพิ่มข้อมูลใหม่ (ออกกำลังกาย, เทมเพลต, เป้าหมาย/มื้ออาหาร) ถ้าไม่อัปเดต Rules จะขึ้น `permission-denied` และบันทึกส่วนใหม่ไม่ได้
Firebase Console → **Firestore Database → Rules** → คัดลอก **`firestore.rules`** ไฟล์ล่าสุดไปวางทับ → **Publish**

### B) แก้ปัญหา Gemini (ถ่ายรูปอาหาร/ฉลาก, ค้นหา AI)
1. **คีย์เก็บแยกในแต่ละเครื่อง** — ใส่ที่มือถือด้วย: ตั้งค่า → Gemini → วางคีย์ → **บันทึก** → กด **ทดสอบการเชื่อมต่อ**
2. ผลทดสอบจะบอกสาเหตุจริง เช่น คีย์ผิด (400), ถูกปฏิเสธ (403), โมเดลถูกยกเลิก (404), **โควตาฟรีหมด (429)**
3. ระดับฟรีมีโควตาต่อนาที/ต่อวันที่ Google ปรับเปลี่ยนได้ — ถ้าหมด ให้ใช้แหล่งอื่นด้านล่างแทน
4. ถ้าทดสอบผ่านแล้วแต่ยังใช้ไม่ได้ ให้ส่งข้อความผลทดสอบมาดู

### C) แหล่งข้อมูลโภชนาการฟรีเพิ่มเติม (ค้นหาโภชนาการ → เลือกแหล่งที่ได้)
| แหล่ง | เหมาะกับ | ต้องตั้งค่า |
|---|---|---|
| Open Food Facts | สินค้าซอง/ขนม/เครื่องดื่ม ค้นด้วยชื่อหรือ **บาร์โค้ด** | ไม่ต้อง (จำกัด ~10 ครั้ง/นาที, ข้อมูลมาจากผู้ใช้ ควรตรวจกับฉลาก) |
| USDA FoodData Central | วัตถุดิบทั่วไป พิมพ์ชื่ออังกฤษ | ขอคีย์ฟรีที่ https://fdc.nal.usda.gov/api-key-signup แล้ววางใน ตั้งค่า |
| Gemini AI | เมนูไทย (ประมาณค่า) | คีย์ Gemini |

> หมายเหตุ: ยังไม่ได้ทดสอบกับเซิร์ฟเวอร์จริงของ Open Food Facts / USDA (เครื่องที่ผมใช้ต่อออกไปไม่ได้) — ถ้าขึ้นข้อความผิดพลาดให้แจ้งข้อความนั้นมา

## อัปเดต v1.4
- Firestore Rules Production ถูกอัปเดตจาก `main` เมื่อ 12 พ.ย. 2026; ถ้าตั้งค่าโปรเจกต์ใหม่ ให้ publish ไฟล์ `firestore.rules` ล่าสุดจาก branch `main` เท่านั้น
- ค้นหาแบบ “ทุกแหล่ง” จะเรียก Open Food Facts, USDA และ Gemini พร้อมกัน; แหล่งที่ยังไม่มี API key หรือถูกจำกัดโควตาจะแสดงสถานะ ส่วนแหล่งอื่นยังค้นหาต่อ
- Google และ ChatGPT เป็นลิงก์ค้นหาแยกภายนอกเพื่อไม่ใช้ API ที่ต้องมีคีย์/อาจมีค่าใช้จ่าย; ผลจากสองเว็บนี้ไม่ถูกรวมในรายการโภชนาการ
- หน้าตั้งค่ารวมคีย์ Gemini และ USDA ไว้หมวดเดียวท้ายหน้า คีย์ยังคงอยู่เฉพาะเบราว์เซอร์อุปกรณ์นั้น
- GitHub Actions workflow สำหรับ build คือ `.github/workflows/build.yml`; workflow deploy Pages คือ `.github/workflows/pages.yml`

### D) ตั้งเป้าแคลอรี่และมื้ออาหาร
ตั้งค่า → **เป้าหมายพลังงาน (BMI / TDEE)** กรอกเพศ ปีเกิด ส่วนสูง น้ำหนัก ระดับกิจกรรม และเป้าหมาย → **บันทึก** (น้ำหนักจะใช้ค่าล่าสุดจากแท็บน้ำหนักก่อนเสมอ)
ส่วน **มื้ออาหารของฉัน** เพิ่ม/ลบ/เปลี่ยนชื่อมื้อและตั้งสัดส่วน % ได้

### E) ถ้ามือถือยังแสดงผลเพี้ยน
ล้างแคช/ปิดแอปแล้วเปิดใหม่ให้ได้เวอร์ชันล่าสุด (แอปอัปเดตตัวเองตอนเปิดครั้งถัดไป) ถ้ายังเห็นอาการเดิม แจ้งรุ่นเครื่อง + เบราว์เซอร์ + ภาพหน้าจอ

## อัปเดต v1.5 — ต้องทำหลังได้โค้ดชุดนี้
1. **Publish `firestore.rules` ใหม่** (เพิ่ม collection `lab_records` สำหรับผลตรวจ) — Firebase Console → Firestore Database → Rules → วางทับ → Publish ถ้าไม่ทำ แท็บ "ผลตรวจ" จะบันทึกไม่ได้ (`permission-denied`)
2. เมื่อใส่ปริมาณอาหาร: ถ้าเมนูมีน้ำหนักต่อหน่วยอยู่แล้ว (เช่น "ข้าวสวย 100 g") ช่องจะเป็น **กรัม** อัตโนมัติ — กรอก 55 ได้เลย และสลับเป็น "จำนวนหน่วย" ได้ที่ตัวเลือกเหนือช่อง
3. ค่าแคลอรี่ที่เผาผลาญจากการออกกำลังกายเป็นค่าประมาณ (สูตร MET) ต้องมีน้ำหนักในแท็บน้ำหนักหรือในตั้งค่าและใส่ระยะเวลา
