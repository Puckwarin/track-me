# Project Setup — ตั้งค่า Track Me v5.10.0

เอกสารนี้ใช้สำหรับติดตั้งครั้งแรกหรือย้ายไปยัง Firebase/GitHub project ใหม่ หากใช้งาน Track Me production อยู่แล้ว ให้อ่านหัวข้ออัปเดตและคีย์เสริมด้านล่างก่อนทำซ้ำ การใช้บริการฟรีมีโควตาและข้อจำกัดตามผู้ให้บริการ; ไม่ต้องใส่บัตรเพื่อใช้ GitHub Pages และ Firebase Spark แต่ API ภายนอกอาจจำกัดคำขอหรือขัดข้องชั่วคราว

v4.1.0 เพิ่มงบรายเดือนตามหมวด กฎแนะนำหมวดที่เรียนรู้จากรายจ่ายที่บันทึก/แก้ไข และรายการรายจ่ายประจำที่ต้องยืนยันก่อนบันทึกจริง ข้อมูลเหล่านี้อยู่ใน `users/{uid}/settings` และรวมอยู่ใน backup โดยไม่รวม Push subscription

สำหรับ workflow ปัจจุบัน ใช้ `.github/workflows/build.yml` ตรวจ lint/tests/Rules Emulator/build และ deploy GitHub Pages จาก `main` หลัง checks ผ่าน; ไม่มี `pages.yml` แยกแล้ว

> ⚠️ **ลำดับสำคัญ:** ทำตามเลขข้อต่อกันไป โดยเฉพาะข้อ 4–6 (ย้ายข้อมูลเดิม) — ถ้าเปลี่ยน Rules เป็นแบบสุดท้ายก่อนย้ายข้อมูล ข้อมูลเดิมจะอ่านไม่ได้

## 0) สิ่งที่ต้องมี
- บัญชี Google (ใช้ทั้ง Firebase และล็อกอินในแอป)
- บัญชี GitHub และ repo `Puckwarin/track-me` (ตั้งเป็น **Public** — GitHub Pages ฟรีใช้กับ repo สาธารณะ; repo ส่วนตัวต้องใช้แผนเสียเงิน)
- (ถ้าจะพัฒนา/ทดสอบบนเครื่อง) Node.js 24.12 ขึ้นไป; Firestore Emulator ต้องใช้ Java 21 ขึ้นไป

## 1) Firebase: ตรวจแผนและเปิด Google Sign-in
เปิด [Firebase Console](https://console.firebase.google.com) → เลือกโปรเจกต์ `trackme-2829`

1. **ตรวจแผน:** มุมซ้ายล่างต้องเป็น **Spark (No-cost)** — ไม่ต้องกด Upgrade เลย
2. ไปที่ **Build → Authentication → Get started** (ถ้ายังไม่เคยเปิด)
3. แท็บ **Sign-in method** → เลือก **Google** → เปิด **Enable** → ใส่ *Project support email* (อีเมลของคุณ) → **Save**
4. แท็บ **Settings → Authorized domains** → **Add domain** ใส่ `puckwarin.github.io`
   (`localhost` มีอยู่แล้วโดยปริยาย สำหรับพัฒนาบนเครื่อง)

## 2) ดันโค้ดขึ้น GitHub และเปิด GitHub Pages
1. อัปโหลด/push โค้ดทั้งโฟลเดอร์ขึ้น branch `main` (รวมโฟลเดอร์ `.github/workflows/` และ `package-lock.json`)
2. ใน GitHub: **Settings → Pages → Build and deployment → Source** เลือก **GitHub Actions**
   (ของเดิมน่าจะเป็น "Deploy from a branch" — ต้องเปลี่ยน ไม่เช่นนั้นจะเห็นหน้าเปล่า)
3. ดูแท็บ **Actions** ให้ workflow "Quality checks and deploy" ขึ้นเขียว (ใช้เวลา 1–2 นาที)
4. เว็บอยู่ที่ `https://puckwarin.github.io/track-me/`

## 3) Firestore Rules ชุดย้ายข้อมูล (ชั่วคราว)
Firebase Console → **Build → Firestore Database → Rules**

> **คำเตือนด้านความเป็นส่วนตัว:** ขณะใช้ `firestore.rules.migration` ผู้ใช้ที่ล็อกอินคนใดก็ได้อาจอ่านหรือลบข้อมูล Room Code เดิมใน `food_records`, `period_records` และ `body_records` ได้ กฎนี้ไม่จำกัดการเข้าถึงด้วย Room Code หรือเจ้าของเดิม ใช้เฉพาะช่วงสั้นในเวลาควบคุมการย้าย และสำรองข้อมูลก่อน

1. คัดลอกเนื้อหาไฟล์ **`firestore.rules.migration`** ไปวางทับ → **Publish** เฉพาะเมื่อเริ่มย้ายข้อมูล

## 4) ล็อกอินและย้ายข้อมูลเดิม (ประวัติการติดตั้งรุ่นเก่า)
1. เปิดเว็บ → กด **เข้าสู่ระบบด้วย Google**
2. **หมายเหตุตั้งแต่ v5.9.0:** หน้าตั้งค่าปัจจุบันนำกล่องย้ายข้อมูล Room Code ออกจาก UI แล้ว (คงเฉพาะส่วนตั้งค่า, สำรองข้อมูล และคีย์เสริม); สำหรับโปรเจกต์ใหม่ให้ข้ามไปข้อ 5 ใช้ `firestore.rules` ล่าสุดทันที (ไฟล์ `src/migrate.js` ยังคงอยู่ในโค้ดสำหรับอ้างอิงรุ่นเก่า)
3. **สำรองข้อมูล (JSON)** ใน **ตั้งค่า** เก็บไว้เป็นระยะเพื่อความปลอดภัยของข้อมูล

## 5) เปลี่ยนเป็น Rules ชุดสุดท้าย
Firebase Console → **Firestore Database → Rules**

1. เมื่อย้ายและตรวจข้อมูลเสร็จ ให้คัดลอกเนื้อหาไฟล์ **`firestore.rules`** วางทับ → **Publish** ทันที เพื่อปิดสิทธิ์ legacy ชั่วคราว
2. ทดสอบที่แท็บ **Rules Playground**: อ่าน `/users/ไอดีใครก็ได้/food_records/x` โดยไม่ล็อกอิน ต้องเป็น **Denied**
3. กลับมารีเฟรชแอป ต้องเห็นข้อมูลปกติ

> ข้อมูลเดิมแบบ Room Code (collection ระดับบน) จะอ่านไม่ได้แล้ว — ถ้าต้องการลบทิ้ง ให้กดปุ่ม "ลบข้อมูลเดิมในห้องนี้" ในหน้าย้ายข้อมูล **ก่อน** ทำข้อ 5 หรือลบเองใน Firebase Console

ดูโครงสร้าง collection, query และข้อควรระวังของกฎได้ที่ [docs/FIRESTORE_SCHEMA.md](FIRESTORE_SCHEMA.md)

## 6) (ตัวเลือก) Gemini API Key สำหรับถ่ายรูปอาหาร/ฉลาก
ฟีเจอร์ AI ใช้คีย์ **ของคุณเอง** และเรียก provider จาก browser โดยตรง (ยังไม่มี backend proxy)

1. เข้า [Google AI Studio → API keys](https://aistudio.google.com/apikey) → **Create API key** (ระดับฟรีไม่ต้องผูกบัตร)
2. คัดลอกคีย์ → ในแอป **ตั้งค่า → Gemini API Key** → วาง → บันทึก
3. ต้องใส่ **ทุกอุปกรณ์** (คีย์เก็บในเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่ซิงค์ ไม่อยู่ในไฟล์สำรอง)
4. อย่าเอาคีย์ไปใส่ในโค้ดหรือ push ขึ้น GitHub — ถ้าคีย์หลุดให้ลบแล้วสร้างใหม่ใน AI Studio
5. โควตาและเงื่อนไขของระดับฟรีเปลี่ยนได้ (รวมถึงเรื่องการใช้ข้อมูลที่ส่งไป) — ตรวจหน้าเว็บของ Google ก่อนใช้ ภาพอาหาร/ฉลากที่ส่งจะถูกส่งไปที่ Google


## 6.1) คีย์ AI สำรอง, OCR และทดสอบการเชื่อมต่อ (ตัวเลือก)
คีย์เหล่านี้ต้องสมัครและสร้างเอง แอปไม่สร้างคีย์หรือส่งไปเก็บบน Firebase และเก็บใน localStorage ของเบราว์เซอร์อุปกรณ์นี้เท่านั้น

- **Gemini**: สร้าง API key ที่ [Google AI Studio](https://aistudio.google.com/apikey) แล้ววางใน ตั้งค่า → Gemini API Key → กด **บันทึก** แล้วกด **ทดสอบการเชื่อมต่อ** ระบบค้นหาโมเดลที่รองรับงานและสลับไป provider ถัดไปเมื่อใช้ไม่ได้
- **Groq**: สร้าง API key จาก [Groq Console](https://console.groq.com/keys) แล้วบันทึกที่ ตั้งค่า → Groq API Key → กด **ทดสอบการเชื่อมต่อ** ระบบค้นหาโมเดลข้อความ/ภาพจาก API และใช้ candidate สำรองเมื่อค้นหารายชื่อไม่ได้ชั่วคราว
- **OpenRouter (ตัวเลือก)**: สร้าง API key จาก [OpenRouter](https://openrouter.ai/keys) แล้วบันทึกที่ ตั้งค่า → OpenRouter API Key → กด **ทดสอบการเชื่อมต่อ** ระบบเลือกเฉพาะโมเดลฟรีที่เข้ากับงาน
- Provider กลางจะเรียง **Gemini → Groq → OpenRouter**, ข้าม provider ที่ไม่มีคีย์หรือติด cooldown; งานค้นหาโภชนาการจะค้น **คลังอาหารในเครื่อง → USDA → Open Food Facts → AI** ก่อนตามลำดับ
- อ่านฉลากจะลอง OCR ด้วย Tesseract.js ฝั่งเบราว์เซอร์ก่อน; ค่า OCR เป็นร่าง ต้องตรวจรูปและหน่วยก่อนบันทึก หาก OCR ไม่ครบจึงส่งภาพให้ AI ตามลำดับ fallback
- **USDA**: ขอคีย์ฟรีที่ [FoodData Central](https://fdc.nal.usda.gov/api-key-signup/) แล้วบันทึกในช่อง USDA API Key พร้อมปุ่ม **ทดสอบการเชื่อมต่อ** เพื่อเช็กคีย์ การค้นหาปกติใช้คลังในเครื่องก่อน แล้ว USDA และ Open Food Facts ก่อนส่งต่อ AI เมื่อไม่พบข้อมูล

> คีย์ฝั่ง browser ไม่ได้เข้ารหัสเป็น secret และผู้ให้บริการจะได้รับ prompt/รูปภาพที่ส่งวิเคราะห์; ตั้งค่าใหม่แยกในแต่ละอุปกรณ์ และตรวจข้อกำหนดการใช้ข้อมูลของ provider ก่อนใช้งาน ดูรายละเอียด cooldown, retry และ privacy ได้ที่ [docs/AI_SERVICE.md](AI_SERVICE.md)

## 6.2) เริ่มต้นใช้งานครั้งแรก (ตัวเลือก)

บัญชี Google ที่เพิ่งสร้างใน Firebase และยังไม่มีโปรไฟล์จะแสดงขั้นตอนแนะนำ 5 ขั้น: แนะนำแอป, โปรไฟล์พื้นฐาน, AI, การแจ้งเตือน และพร้อมใช้งาน ผู้ใช้เดิมหรือบัญชีที่มีโปรไฟล์จะไม่ถูกบังคับผ่าน onboarding

- กรอกข้อมูลโปรไฟล์ครบจึงจะบันทึกเพื่อใช้คำนวณ BMI/BMR/เป้าหมายได้; หากยังไม่สะดวกให้ข้ามได้ และเพิ่มหรือแก้ไขภายหลังที่ **ตั้งค่า → เป้าหมายพลังงาน**
- การตั้งค่า AI และการแจ้งเตือนเป็นทางเลือก การทดสอบคีย์จะเรียก API เมื่อกดปุ่มเองเท่านั้น; provider อาจมีโควตาหรือค่าใช้จ่าย โปรดตรวจเงื่อนไขก่อนใช้งาน
- ความคืบหน้า onboarding เก็บใน `localStorage` แยกตามบัญชีและอุปกรณ์เพื่อกลับมาทำต่อหลังเปิดแอปใหม่; การตั้งค่าคีย์ AI ยังคงเก็บเฉพาะเบราว์เซอร์ ส่วนโปรไฟล์ที่บันทึกจะซิงค์ผ่าน Firestore
- การแจ้งเตือนจะขอสิทธิ์จากเบราว์เซอร์หลังผู้ใช้กด **เปิดการแจ้งเตือน** เท่านั้น; ปฏิเสธหรือข้ามได้โดยไม่กระทบการใช้ฟีเจอร์หลัก

## Hiwpinto Sync Helper (ทำครั้งเดียว)

ตั้งค่า Bookmark สำหรับดึงเมนูอาหารจาก Hiwpinto ใช้เพียงครั้งเดียวต่อเบราว์เซอร์

1. เปิดหน้าต่าง **Sync Data Hiwpinto** ในแอป Track Me แล้วกดปุ่ม **คัดลอก Sync Helper**
2. เปิดแถบ Bookmark ของเบราว์เซอร์ (กด `Cmd + Shift + B` บน Mac หรือ `Ctrl + Shift + B` บน Windows) แล้วเลือกเพิ่มหน้าเว็บใหม่ (**Add page / Add bookmark**)
3. ตั้งชื่อว่า `Sync Hiwpinto` และวางโค้ดที่คัดลอกไว้ลงในช่อง URL จากนั้นกดบันทึก

## 7) พัฒนาบนเครื่อง (ตัวเลือก)
```bash
npm ci               # ใช้ npm ci เพื่อไม่อัปเดต package-lock.json โดยไม่ตั้งใจ
npm run lock:check   # ตรวจว่าไม่ขาด optional platform packages ใน package-lock.json
npm run dev          # เปิด http://localhost:3000/
npm run build        # ผลลัพธ์ที่ dist/
```

> **หมายเหตุเรื่อง `package-lock.json` บน Linux container:** หลีกเลี่ยงการรัน `npm install` (แบบไม่ใส่ `--no-save` / `npm ci`) บนสภาพแวดล้อม Linux container แล้ว commit `package-lock.json` ทับ เพราะ npm อาจตัด `optionalDependencies` ของ macOS/Windows (เช่น `@tailwindcss/oxide-*`, `@esbuild/*`, `rollup`) ออกจนทำให้ CI (`npm ci`) ล้มได้ ให้ตรวจด้วย `npm run lock:check` ก่อน commit เสมอ
>
> **หมายเหตุเรื่องข้อมูล Zepp (การนอนหลับ & ก้าวเดิน):** Track Me เป็นเว็บแอป (PWA) ฝั่งเบราว์เซอร์ จึงไม่สามารถเข้าถึงฐานข้อมูลภายในแอป Zepp บนมือถือโดยตรงหรือล็อกอิน Zepp OAuth แบบไม่ผ่าน API สาธารณะได้ แอปจึงรองรับการบันทึก 3 วิธีในเมนู **ร่างกาย (`น้ำหนัก · นอน/ก้าว`)**: (1) กรอกเอง, (2) นำเข้าไฟล์ CSV Export จากแอป Zepp (`ACTIVITY*.csv` + `SLEEP*.csv` เลือกพร้อมกันได้ ระบบรวมตามวันที่และให้ตรวจยืนยันก่อนบันทึก), และ (3) สแกนภาพหน้าจอแอป Zepp ด้วย AI Vision

## 8) ติดตั้งเป็นแอปบนมือถือ + ทดสอบออฟไลน์
1. เปิด `https://puckwarin.github.io/track-me/` ตอนออนไลน์ ล็อกอิน แล้วรอให้ข้อมูลโหลด **1–2 ครั้ง**
2. Android (Chrome): เมนู ⋮ → **Add to Home screen / Install app** · iPhone (Safari): ปุ่มแชร์ → **Add to Home Screen**
3. ทดสอบ: เปิดโหมดเครื่องบิน → เปิดแอป → ต้องเห็นการ์ด "สรุปสุขภาพล่าสุด" พร้อมเวลาซิงค์ล่าสุด และบันทึกข้อมูลใหม่ได้ (ป้ายขึ้น "ออฟไลน์ · รอซิงค์") พอกลับมาออนไลน์จะซิงค์เอง

## แก้ปัญหาที่พบบ่อย
| อาการ | วิธีแก้ |
|---|---|
| `auth/unauthorized-domain` | เพิ่ม `puckwarin.github.io` ใน Authentication → Settings → Authorized domains (ข้อ 1.4) |
| `auth/operation-not-allowed` | ยังไม่ได้ Enable Google ใน Sign-in method (ข้อ 1.3) |
| ป้ายเป็นสีแดง `permission-denied` | Rules ยังไม่ได้ Publish / ยังไม่ล็อกอิน / ใช้ชุด Rules ผิดขั้นตอน (ดูข้อ 3 และ 5) |

## อัปเดต v2.6 (ตั้งค่าการแจ้งเตือนอัตโนมัติ Push Notification 12:15 น. ฟรี)

ระบบแจ้งเตือนโดยไม่ต้องเปิดแอปค้างไว้ ใช้ **Web Push (VAPID) + GitHub Actions** ฟรีทั้งหมด ไม่ต้องผูกบัตรเครดิต:

1. **ไม่ต้องอัปเดต Firestore Rules**: ข้อมูล Weekly Planner (`settings/planner`) และการสมัครรับ Push (`settings/push`) ใช้ collection `settings` ที่มีอยู่แล้วใน `firestore.rules`
2. **สร้างคู่กุญแจ VAPID (ทำครั้งเดียวในเครื่อง/Terminal)**:
   ```bash
   npx web-push generate-vapid-keys
   ```
   จะได้ค่า **Public Key** และ **Private Key** เก็บไว้สำหรับข้อ 4
3. **สร้าง Firebase Service Account Key** (ฟรีในแผน Spark ไม่ต้องผูกบัตร):
   - เข้า [Firebase Console](https://console.firebase.google.com) → โปรเจกต์ของคุณ → ไอคอนฟันเฟือง **Project settings → Service accounts**
   - กด **Generate new private key** → จะได้ไฟล์ `.json` (เปิดไฟล์ด้วย Text Editor แล้วคัดลอกข้อความทั้งหมด)
4. **ใส่ GitHub Repository Secrets** (GitHub → Repo ของคุณ → **Settings → Secrets and variables → Actions → New repository secret**):
   - `VAPID_PUBLIC_KEY` → วาง Public Key จากข้อ 2
   - `VAPID_PRIVATE_KEY` → วาง Private Key จากข้อ 2
   - `VAPID_SUBJECT` → ใส่อีเมลติดต่อในรูปแบบ `mailto:your-email@gmail.com`
   - `FIREBASE_SERVICE_ACCOUNT` → วางข้อความ JSON ทั้งหมดจากข้อ 3
5. **Deploy ใหม่ & เปิดรับการแจ้งเตือนบนมือถือ**:
   - เมื่อ workflow **Quality checks and deploy** build บน `main` เว็บจะฝัง `VITE_VAPID_PUBLIC_KEY` ให้อัตโนมัติ; การกด Run workflow จาก branch อื่นไม่ deploy Pages
   - เปิดแอป Track Me → กดปุ่ม **"🔔 เปิดรับการแจ้งเตือน"** ที่หน้า Home หรือใน **ตั้งค่า**
   - **หมายเหตุ iPhone / iPad (iOS 16.4+):** ต้องกดปุ่ม **แชร์ (Share) → เพิ่มไปยังหน้าจอโฮม (Add to Home Screen)** แล้วเปิดแอปจากไอคอนบนหน้าจอก่อนจึงจะกดเปิดรับแจ้งเตือนได้
   - ทดสอบส่งได้ทันทีใน GitHub → **Actions → Daily Push Notifications (12:15 ICT) → Run workflow** (ปกติระบบจะทำงานอัตโนมัติทุกวันเวลา **12:15 น. เวลาประเทศไทย**)

    - ไม่ต้องสร้าง Firestore Collection Group Index ด้วยมือแล้ว เพราะสคริปต์อ่านตรงจาก `users` → `settings/push` และเติม `mailto:` หน้า `VAPID_SUBJECT` ให้อัตโนมัติ

## อัปเดต v3.0.0 (ย้ายรายจ่ายเป็น `expense_records`, ป้องกัน AI Injection, ความเป็นส่วนตัว Push & IAM ขั้นต่ำ)

### 1) ต้องเผยแพร่ `firestore.rules` ใหม่ (เพิ่ม `expense_records`)
- เวอร์ชัน v3.0.0 เพิ่ม collection **`expense_records`** (1 เอกสาร = 1 รายการรายรับ-รายจ่าย) เพื่อกันข้อมูลทับกันและรองรับการซิงค์ออฟไลน์ข้ามเครื่อง
- **ขั้นตอนที่ต้องทำใน Firebase Console:**
  1. เปิด **Firebase Console → Build → Firestore Database → Rules**
  2. คัดลอกเนื้อหาล่าสุดจากไฟล์ **`firestore.rules`** ใน branch `main` ไปวางทับ → กด **Publish**
- **การย้ายข้อมูลเดิมอัตโนมัติ:** หลัง Publish Rules แล้ว เมื่อเปิดแอปและออนไลน์ แอปจะย้ายรายการเก่าจาก `settings/exp_YYYY-MM` เข้าสู่ `expense_records` ให้อัตโนมัติแบบ Idempotent (ไม่เกิดรายการซ้ำ และไม่ลบของเดิมจนกว่าจะย้ายสำเร็จ) ส่วนไฟล์สำรอง JSON เวอร์ชันเก่าก็ยังกู้คืนได้ปกติ

### 2) การตั้งค่า Push Privacy & Backup
- **หน้าจอล็อกส่วนตัว (ค่าเริ่มต้นเปิด):** ในหน้า **ตั้งค่า → การแจ้งเตือนอัตโนมัติ (12:15 น.)** มีตัวเลือก **"🔒 ซ่อนรายละเอียดส่วนตัวบนหน้าจอล็อก (แนะนำ)"** ซึ่งจะส่งเฉพาะสรุปจำนวนรายการรวม (ไม่แสดงชื่อรอบเดือน ยา หรือรายการนัดบนหน้าจอล็อก) หากต้องการให้แสดงรายชื่อหัวข้อบนแจ้งเตือน สามารถติ๊กออกได้เอง
- **ไฟล์สำรองข้อมูล (Backup JSON):** ระบบตัดเอกสาร `settings/push` (Subscription Endpoint และ Keys ของเครื่อง) ออกจากการส่งออกและนำเข้าโดยอัตโนมัติ

### 3) จำกัดสิทธิ์ `FIREBASE_SERVICE_ACCOUNT` ตามหลัก Least-Privilege (แนะนำ)
แทนการใช้ Service Account สิทธิ์กว้างระดับ **Firebase Admin SDK Administrator / Editor / Owner** คุณสามารถสร้าง **Custom IAM Role** ที่มีสิทธิ์เฉพาะเท่าที่ `scripts/daily-push.mjs` ใช้จริงได้ใน Google Cloud Console:
1. เปิด [Google Cloud Console → IAM & Admin → Roles](https://console.cloud.google.com/iam-admin/roles) (เลือกโปรเจกต์ `trackme-2829` ของคุณ) → กด **Create Role**
2. เพิ่มสิทธิ์ (Permissions) ดังนี้เท่านั้น:
   - `datastore.entities.get`
   - `datastore.entities.list`
   - `datastore.entities.update` *(ใช้เฉพาะตอนลบ Push Endpoint ที่หมดอายุ 404/410 ออกจาก `settings/push`)*
3. ไปที่ **IAM & Admin → Service Accounts** → สร้าง Service Account ใหม่ (เช่น `trackme-daily-push`) แล้วผูกเฉพาะ **Custom Role** ข้างต้น → สร้าง Key JSON ใหม่ไปอัปเดตใน GitHub Secret `FIREBASE_SERVICE_ACCOUNT` (และลบ Key เก่าออก)

  2. `date,deepSleepTime,shallowSleepTime,wakeTime,start,stop,REMTime,naps` — สรุปการนอนรายวัน (นาที) พร้อมเวลาเข้านอน/ตื่นจาก `start`/`stop`, นาทีตื่นระหว่างคืน และการงีบ (`naps`)
  3. `date,steps,distance,runDistance,calories` — ก้าวเดิน, ระยะทาง (แปลงเมตรเป็น กม.), ระยะวิ่ง และแคลอรี่
