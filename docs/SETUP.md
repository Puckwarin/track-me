# Project Setup — ตั้งค่า Track Me v3.0.0

เอกสารนี้ใช้สำหรับติดตั้งครั้งแรกหรือย้ายไปยัง Firebase/GitHub project ใหม่ หากใช้งาน Track Me production อยู่แล้ว ให้อ่านหัวข้ออัปเดตและคีย์เสริมด้านล่างก่อนทำซ้ำ การใช้บริการฟรีมีโควตาและข้อจำกัดตามผู้ให้บริการ; ไม่ต้องใส่บัตรเพื่อใช้ GitHub Pages และ Firebase Spark แต่ API ภายนอกอาจจำกัดคำขอหรือขัดข้องชั่วคราว

> ⚠️ **ลำดับสำคัญ:** ทำตามเลขข้อต่อกันไป โดยเฉพาะข้อ 4–6 (ย้ายข้อมูลเดิม) — ถ้าเปลี่ยน Rules เป็นแบบสุดท้ายก่อนย้ายข้อมูล ข้อมูลเดิมจะอ่านไม่ได้

## 0) สิ่งที่ต้องมี
- บัญชี Google (ใช้ทั้ง Firebase และล็อกอินในแอป)
- บัญชี GitHub และ repo `Puckwarin/track-me` (ตั้งเป็น **Public** — GitHub Pages ฟรีใช้กับ repo สาธารณะ; repo ส่วนตัวต้องใช้แผนเสียเงิน)
- (ถ้าจะพัฒนาบนเครื่อง) Node.js 22 ขึ้นไป

## 1) Firebase: ตรวจแผนและเปิด Google Sign-in
เปิด [Firebase Console](https://console.firebase.google.com) → เลือกโปรเจกต์ `trackme-2829`

1. **ตรวจแผน:** มุมซ้ายล่างต้องเป็น **Spark (No-cost)** — ไม่ต้องกด Upgrade เลย
2. ไปที่ **Build → Authentication → Get started** (ถ้ายังไม่เคยเปิด)
3. แท็บ **Sign-in method** → เลือก **Google** → เปิด **Enable** → ใส่ *Project support email* (อีเมลของคุณ) → **Save**
4. แท็บ **Settings → Authorized domains** → **Add domain** ใส่ `puckwarin.github.io`
   (`localhost` มีอยู่แล้วโดยปริยาย สำหรับพัฒนาบนเครื่อง)

## 2) ดันโค้ดขึ้น GitHub และเปิด GitHub Pages
1. อัปโหลด/push โค้ดทั้งโฟลเดอร์ขึ้น branch `main` (รวมโฟลเดอร์ `.github/workflows/` และ `package-lock.json`)
2. ใน GitHub: **Settings → Pages → Build and deployment → Source** เลือก **GitHub Actions**
   (ของเดิมน่าจะเป็น "Deploy from a branch" — ต้องเปลี่ยน ไม่เช่นนั้นจะเห็นหน้าเปล่า)
3. ดูแท็บ **Actions** ให้ workflow "Deploy to GitHub Pages" ขึ้นเขียว (ใช้เวลา 1–2 นาที)
4. เว็บอยู่ที่ `https://puckwarin.github.io/track-me/`

## 3) Firestore Rules ชุดย้ายข้อมูล (ชั่วคราว)
Firebase Console → **Build → Firestore Database → Rules**

1. คัดลอกเนื้อหาไฟล์ **`firestore.rules.migration`** ไปวางทับ → **Publish**
   (ชุดนี้ให้เฉพาะผู้ที่ล็อกอินแล้วอ่านข้อมูล Room Code เดิมได้ชั่วคราว)

## 4) ล็อกอินและย้ายข้อมูลเดิม
1. เปิดเว็บ → กด **เข้าสู่ระบบด้วย Google**
2. ไปที่ **ตั้งค่า → ย้ายข้อมูลจาก Room Code เดิม** → ใส่รหัสห้องเดิม (ถ้าเคยตั้งในเครื่องนั้นไว้ ช่องจะกรอกให้) → **ตรวจสอบ**
3. กด **ย้ายเข้าบัญชีนี้** → ตรวจในแท็บอาหาร/ประจำเดือน/น้ำหนักว่าข้อมูลครบ (ย้ายซ้ำได้ ไม่เกิดข้อมูลซ้ำ)
4. **แนะนำ:** กด **สำรองข้อมูล (JSON)** ใน ตั้งค่า เก็บไว้ก่อน
5. ถ้ามีหลายห้อง/หลายอุปกรณ์ที่เคยใช้รหัสห้องคนละรหัส ให้ทำข้อ 2–3 ซ้ำกับแต่ละรหัส

## 5) เปลี่ยนเป็น Rules ชุดสุดท้าย
Firebase Console → **Firestore Database → Rules**

1. คัดลอกเนื้อหาไฟล์ **`firestore.rules`** วางทับ → **Publish**
2. ทดสอบที่แท็บ **Rules Playground**: อ่าน `/users/ไอดีใครก็ได้/food_records/x` โดยไม่ล็อกอิน ต้องเป็น **Denied**
3. กลับมารีเฟรชแอป ต้องเห็นข้อมูลปกติ

> ข้อมูลเดิมแบบ Room Code (collection ระดับบน) จะอ่านไม่ได้แล้ว — ถ้าต้องการลบทิ้ง ให้กดปุ่ม "ลบข้อมูลเดิมในห้องนี้" ในหน้าย้ายข้อมูล **ก่อน** ทำข้อ 5 หรือลบเองใน Firebase Console

## 6) (ตัวเลือก) Gemini API Key สำหรับถ่ายรูปอาหาร/ฉลาก
ฟีเจอร์ AI ใช้คีย์ **ของคุณเอง** (ผมทำ backend ให้ไม่ได้ในแผนฟรี)

1. เข้า [Google AI Studio → API keys](https://aistudio.google.com/apikey) → **Create API key** (ระดับฟรีไม่ต้องผูกบัตร)
2. คัดลอกคีย์ → ในแอป **ตั้งค่า → Gemini API Key** → วาง → บันทึก
3. ต้องใส่ **ทุกอุปกรณ์** (คีย์เก็บในเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่ซิงค์ ไม่อยู่ในไฟล์สำรอง)
4. อย่าเอาคีย์ไปใส่ในโค้ดหรือ push ขึ้น GitHub — ถ้าคีย์หลุดให้ลบแล้วสร้างใหม่ใน AI Studio
5. โควตาและเงื่อนไขของระดับฟรีเปลี่ยนได้ (รวมถึงเรื่องการใช้ข้อมูลที่ส่งไป) — ตรวจหน้าเว็บของ Google ก่อนใช้ ภาพอาหาร/ฉลากที่ส่งจะถูกส่งไปที่ Google


## 6.1) คีย์ AI สำรอง, OCR และทดสอบการเชื่อมต่อ (ตัวเลือก)
คีย์เหล่านี้ต้องสมัครและสร้างเอง แอปไม่สร้างคีย์หรือส่งไปเก็บบน Firebase และเก็บใน localStorage ของเบราว์เซอร์อุปกรณ์นี้เท่านั้น

- **Gemini**: สร้าง API key ที่ [Google AI Studio](https://aistudio.google.com/apikey) แล้ววางใน ตั้งค่า → Gemini API Key → กด **บันทึก** แล้วกด **ทดสอบการเชื่อมต่อ** (ลองสลับโมเดลอัตโนมัติ `gemini-3.8-flash` → `gemini-3.6-flash` → `gemini-3.5-flash-lite` พร้อม Timeout 35 วินาทีต่อโมเดล และวนข้ามอัตโนมัติเมื่อเกิด Timeout หรือ 429 Quota/Rate Limit)
- **Groq**: สร้าง API key จาก [Groq Console](https://console.groq.com/keys) แล้วบันทึกที่ ตั้งค่า → Groq API Key → กด **ทดสอบการเชื่อมต่อ** (งานข้อความ/JSON Mode ใช้ `llama-3.3-70b-versatile` / `llama-3.1-8b-instant` และงานภาพใช้ `llama-3.2-11b-vision-preview` / โมเดล Vision ที่เปิดในบัญชี)
- การค้นหาโภชนาการอัตโนมัติจะค้นตามลำดับ **คลังอาหารในเครื่อง → USDA → Open Food Facts → Groq → Gemini (Fallback)** ส่วนงานวิเคราะห์ภาพ (อาหารจานโปรด, ซองอาหารสัตว์เลี้ยง, และใบผลตรวจ) จะลอง **Gemini → Groq** ตามคีย์ที่มี และสลับเมื่อคำขอล้มเหลว/โควตาเต็ม คำขอรูปส่งตรงให้ผู้ให้บริการนั้น ตรวจนโยบายข้อมูลก่อนใช้รูปส่วนตัว
- อ่านฉลากจะลอง OCR ด้วย Tesseract.js ฝั่งเบราว์เซอร์ก่อน; ค่า OCR เป็นร่าง ต้องตรวจรูปและหน่วยก่อนบันทึก หาก OCR ไม่ครบจึงส่งภาพให้ AI ตามลำดับ fallback
- **USDA**: ขอคีย์ฟรีที่ [FoodData Central](https://fdc.nal.usda.gov/api-key-signup/) แล้วบันทึกในช่อง USDA API Key พร้อมปุ่ม **ทดสอบการเชื่อมต่อ** เพื่อเช็กคีย์ การค้นหาปกติใช้คลังในเครื่องก่อน แล้ว USDA และ Open Food Facts ก่อนส่งต่อ AI เมื่อไม่พบข้อมูล

## Hiwpinto Sync Helper (ทำครั้งเดียว)

ตั้งค่า Bookmark สำหรับดึงเมนูอาหารจาก Hiwpinto ใช้เพียงครั้งเดียวต่อเบราว์เซอร์

1. เปิดหน้าต่าง **Sync Data Hiwpinto** ในแอป Track Me แล้วกดปุ่ม **คัดลอก Sync Helper**
2. เปิดแถบ Bookmark ของเบราว์เซอร์ (กด `Cmd + Shift + B` บน Mac หรือ `Ctrl + Shift + B` บน Windows) แล้วเลือกเพิ่มหน้าเว็บใหม่ (**Add page / Add bookmark**)
3. ตั้งชื่อว่า `Sync Hiwpinto` และวางโค้ดที่คัดลอกไว้ลงในช่อง URL จากนั้นกดบันทึก

| Pop-up ล็อกอินถูกบล็อก | อนุญาต pop-up ของเว็บนี้ในเบราว์เซอร์ |

## ขีดจำกัดแผนฟรี (Spark) ที่ควรรู้
- Firestore: อ่าน 50,000 ครั้ง/วัน (ใช้คนเดียวเหลือเฟือ) — เลิกฟังข้อมูลเมื่อไม่ใช้ แอปนี้ดึงเฉพาะข้อมูลที่ต้องใช้
- ถ้าเกินโควตา Firebase จะหยุดให้บริการจนถึงวันถัดไป **ไม่เรียกเก็บเงิน** (เพราะไม่ได้ผูกบัตร)
- ต้องไม่กด Upgrade เป็น Blaze ถ้าไม่ต้องการผูกบัตร

## ความเป็นส่วนตัวบนอุปกรณ์ร่วม
หลังออกจากระบบ ข้อมูลที่เคยโหลดอาจยังค้างในแคชของเบราว์เซอร์เครื่องนั้น — ถ้าใช้เครื่องสาธารณะ/เครื่องร่วม ให้ล้างข้อมูลเว็บไซต์ (Clear site data) หลังใช้

## บันทึกการตั้งค่าใน v1.3

### A) Firestore Rules
v1.3 เพิ่ม collections สำหรับฟีเจอร์ใหม่ โปรเจกต์ที่ตั้งค่าใหม่ต้องเผยแพร่ไฟล์ firestore.rules ล่าสุดจาก main; อย่าใช้กฎจาก patch หรือ branch เก่า

### B) แก้ปัญหา Gemini (ถ่ายรูปอาหาร/ฉลาก, ค้นหา AI)
1. **คีย์เก็บแยกในแต่ละเครื่อง** — ใส่ที่มือถือด้วย: ตั้งค่า → Gemini → วางคีย์ → **บันทึก** → กด **ทดสอบการเชื่อมต่อ**
2. ผลทดสอบจะบอกสาเหตุจริง เช่น คีย์ผิด (400), ถูกปฏิเสธ (403), โมเดลถูกยกเลิก (404), **โควตาฟรีหมด (429)**
3. ระดับฟรีมีโควตาต่อนาที/ต่อวันที่ Google ปรับเปลี่ยนได้ — ถ้าหมด ให้ใช้แหล่งอื่นด้านล่างแทน
4. ถ้าทดสอบผ่านแล้วแต่ยังใช้ไม่ได้ ให้ส่งข้อความผลทดสอบมาดู

### C) แหล่งข้อมูลโภชนาการฟรีเพิ่มเติม (ค้นหาโภชนาการ → เลือกแหล่งที่ได้)
| แหล่ง | เหมาะกับ | ต้องตั้งค่า |
|---|---|---|
| Open Food Facts | สินค้าซอง/ขนม/เครื่องดื่ม ค้นด้วยชื่อหรือ **บาร์โค้ด** | ไม่ต้อง (จำกัด ~10 ครั้ง/นาที, ข้อมูลมาจากผู้ใช้ ควรตรวจกับฉลาก) |
| USDA FoodData Central | วัตถุดิบทั่วไป พิมพ์ชื่ออังกฤษ | ขอคีย์ฟรีที่ https://fdc.nal.usda.gov/api-key-signup แล้ววางใน ตั้งค่า |
| Gemini AI | เมนูไทย (ประมาณค่า) | คีย์ Gemini |

> หมายเหตุ: API ภายนอกอาจถูกจำกัดจากเบราว์เซอร์หรือหยุดชั่วคราวได้; อ่านข้อความรายแหล่งในหน้าค้นหา เลือกแหล่งอื่น หรือเปิดเว็บไซต์ Open Food Facts จากลิงก์สำรองได้

## อัปเดต v2.6 (ตั้งค่าการแจ้งเตือนอัตโนมัติ Push Notification 08:00 น. ฟรี)

ระบบแจ้งเตือนโดยไม่ต้องเปิดแอปค้างไว้ ใช้ **Web Push (VAPID) + GitHub Actions** ฟรีทั้งหมด ไม่ต้องผูกบัตรเครดิต:

1. **ไม่ต้องอัปเดต Firestore Rules**: ข้อมูล Weekly Planner (`settings/planner`) และการสมัครรับ Push (`settings/push`) ใช้ collection `settings` ที่มีอยู่แล้วใน `firestore.rules`
2. **สร้างคู่กุญแจ VAPID (ทำครั้งเดียวในเครื่อง/Terminal)**:
   ```bash
   npx web-push generate-vapid-keys
   ```
   จะได้ค่า **Public Key** และ **Private Key** เก็บไว้สำหรับข้อ 4
3. **สร้าง Firebase Service Account Key** (ฟรีในแผน Spark ไม่ต้องผูกบัตร):
   - เข้า [Firebase Console](https://console.firebase.google.com) → โปรเจกต์ของคุณ → ไอคอนฟันเฟือง **Project settings → Service accounts**
   - กด **Generate new private key** → จะได้ไฟล์ `.json` (เปิดไฟล์ด้วย Text Editor แล้วคัดลอกข้อความทั้งหมด)
4. **ใส่ GitHub Repository Secrets** (GitHub → Repo ของคุณ → **Settings → Secrets and variables → Actions → New repository secret**):
   - `VAPID_PUBLIC_KEY` → วาง Public Key จากข้อ 2
   - `VAPID_PRIVATE_KEY` → วาง Private Key จากข้อ 2
   - `VAPID_SUBJECT` → ใส่อีเมลติดต่อในรูปแบบ `mailto:your-email@gmail.com`
   - `FIREBASE_SERVICE_ACCOUNT` → วางข้อความ JSON ทั้งหมดจากข้อ 3
5. **Deploy ใหม่ & เปิดรับการแจ้งเตือนบนมือถือ**:
   - เมื่อ push โค้ดหรือกด **Run workflow** ใน `Deploy to GitHub Pages` แล้ว เว็บจะฝัง `VITE_VAPID_PUBLIC_KEY` ให้อัตโนมัติ
   - เปิดแอป Track Me → กดปุ่ม **"🔔 เปิดรับการแจ้งเตือน"** ที่หน้า Home หรือใน **ตั้งค่า**
   - **หมายเหตุ iPhone / iPad (iOS 16.4+):** ต้องกดปุ่ม **แชร์ (Share) → เพิ่มไปยังหน้าจอโฮม (Add to Home Screen)** แล้วเปิดแอปจากไอคอนบนหน้าจอก่อนจึงจะกดเปิดรับแจ้งเตือนได้
   - ทดสอบส่งได้ทันทีใน GitHub → **Actions → Daily Push Notifications (08:00 ICT) → Run workflow** (ปกติระบบจะทำงานอัตโนมัติทุกวันเวลา **08:00 น. เวลาประเทศไทย**)

    - ไม่ต้องสร้าง Firestore Collection Group Index ด้วยมือแล้ว เพราะสคริปต์อ่านตรงจาก `users` → `settings/push` และเติม `mailto:` หน้า `VAPID_SUBJECT` ให้อัตโนมัติ

- **ไฟล์สำรองข้อมูล (Backup JSON):** ระบบตัดเอกสาร `settings/push` (Subscription Endpoint และ Keys ของเครื่อง) ออกจากการส่งออกและนำเข้าโดยอัตโนมัติ

### 3) จำกัดสิทธิ์ `FIREBASE_SERVICE_ACCOUNT` ตามหลัก Least-Privilege (แนะนำ)
แทนการใช้ Service Account สิทธิ์กว้างระดับ **Firebase Admin SDK Administrator / Editor / Owner** คุณสามารถสร้าง **Custom IAM Role** ที่มีสิทธิ์เฉพาะเท่าที่ `scripts/daily-push.mjs` ใช้จริงได้ใน Google Cloud Console:
1. เปิด [Google Cloud Console → IAM & Admin → Roles](https://console.cloud.google.com/iam-admin/roles) (เลือกโปรเจกต์ `trackme-2829` ของคุณ) → กด **Create Role**
2. เพิ่มสิทธิ์ (Permissions) ดังนี้เท่านั้น:
   - `datastore.entities.get`
   - `datastore.entities.list`
   - `datastore.entities.update` *(ใช้เฉพาะตอนลบ Push Endpoint ที่หมดอายุ 404/410 ออกจาก `settings/push`)*
3. ไปที่ **IAM & Admin → Service Accounts** → สร้าง Service Account ใหม่ (เช่น `trackme-daily-push`) แล้วผูกเฉพาะ **Custom Role** ข้างต้น → สร้าง Key JSON ใหม่ไปอัปเดตใน GitHub Secret `FIREBASE_SERVICE_ACCOUNT` (และลบ Key เก่าออก)
