# Track Me

เว็บแอปบันทึกสุขภาพส่วนตัว: **อาหาร · ประจำเดือน · น้ำหนักและสัดส่วน** — ล็อกอินด้วย Google, ซิงค์ข้ามอุปกรณ์ด้วย Firebase Firestore, ใช้งานออฟไลน์ได้ (PWA)
ใช้แผนฟรีทั้งหมด ไม่ต้องผูกบัตรเครดิต

👉 **ครั้งแรกให้อ่าน [docs/SETUP.md](docs/SETUP.md)** (ขั้นตอนที่ต้องตั้งค่าเอง)

## ฟีเจอร์ (v1.2)
- **สรุปสุขภาพล่าสุด** (เปิดดูตอนพบแพทย์): LMP, รอบเฉลี่ย, น้ำหนัก/สัดส่วนล่าสุด, เวลาซิงค์ล่าสุด — ใช้ได้ออฟไลน์ + ปุ่มคัดลอกข้อความ
- **ประจำเดือน**: บันทึกรอบ, ปฏิทิน, คาดการณ์รอบถัดไป (ค่าประมาณ), เตือนเมื่อเปิดแอป
- **อาการรายวัน**: ปวดท้อง/หลัง/หัว สิว อ่อนเพลีย ท้องอืด (ระดับ 0–3), อารมณ์, ความเครียด, หมายเหตุ
- **น้ำหนัก & สัดส่วน**: อก/เอว/สะโพก + กราฟแนวโน้ม
- **อาหาร**: บันทึกมื้อ, คลังอาหารของฉัน (เพิ่ม/แก้ไข/ลบ/โปรด, ยี่ห้อ, หน่วยบริโภค, น้ำตาล, โซเดียม), ถ่ายรูปจาน, **ถ่ายรูปฉลากโภชนาการ** (Gemini, ต้องตรวจและยืนยันก่อนบันทึก ไม่เดาค่าที่อ่านไม่ออก)
- **รายงานสุขภาพ**: เลือกช่วงวันที่ → พิมพ์/บันทึกเป็น PDF (รองรับไทย) หรือ CSV (เปิดใน Excel)
- **สำรอง/กู้คืน JSON**: เลือกหมวด, ตรวจไฟล์, กันข้อมูลซ้ำ, ยืนยันก่อนเขียน
- **ย้ายข้อมูลจาก Room Code เดิม** เข้าบัญชี Google
- ธีมฟ้า · ชมพู · ม่วง

## สิ่งที่ "ไม่ได้ทำ" เพราะต้องผูกบัตรเครดิต (ต้องใช้แผน Blaze)
| ในแผน v1.2 | สถานะ | ทางเลือกที่ทำแทน |
|---|---|---|
| ย้าย Gemini Key ไป Cloud Functions | ข้าม | ใช้คีย์ของผู้ใช้เอง เก็บเฉพาะในเครื่อง ส่งผ่าน header ไม่ใส่ใน URL |
| Push Notification ตอนปิดเว็บ (ต้องมี backend) | ข้าม | เตือนเมื่อเปิดแอป (แบนเนอร์ + Notification ของเครื่องถ้าอนุญาต) |
| `functions/`, `storage.rules` | ไม่สร้าง | ไม่มีส่วนที่ต้องใช้ |

## โครงสร้างข้อมูล (ต่างจากแผนเล็กน้อย)
ข้อมูลอยู่ใต้ `users/{uid}/<collection>/…` แทนการใส่ `ownerUid` ในทุกเอกสาร — Rules เหลือเงื่อนไขเดียว (`uid` ตรงกับเจ้าของ) ง่ายกว่าและพลาดยากกว่า และไม่ต้องสร้าง composite index
collections: `food_records`, `period_records`, `body_records`, `symptom_records`, `custom_foods`

